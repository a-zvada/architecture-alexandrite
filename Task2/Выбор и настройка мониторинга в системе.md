# Мониторинг

## Мотивация

*   улучшение клиентского опыта: отслеживание ключевых метрик взаимодействия клиентов с нашей системой помогает оперативно обнаруживать и устранять проблемы, что влияет на удовлетворенность клиентов и снижает финансовые потери компании
*   повышение производительности производственного контура: задержки работы в АРМ MES будут оперативно выявляться и исправляться
*   обеспечение масштабируемости и снижение рисков простоев: мониторинг инфраструктуры поможет предсказать перегрузки и своевременно расширять ресурсы, избегая сбоев

## Подход к мониторингу

В данном кейсе имеем следующие проблемы и точки мониторинга:

*   Просроченные заказы: надо отслеживать время обработки запросов (например, расчёт стоимости в MES, синхронизация через RabbitMQ).
*   Медленная работа АРМ MES: нужен мониторинг времени отклика, а также загрузки базы данных.
*   API (B2B, B2C): является основным каналом поступления заказов, надо отслеживать RPS, ошибки API и латентность.
*   Рост нагрузки (+100 заказов в месяц): нужно следить за использованием ресурсов и насыщенностью сервисов, очередей, БД.
*   Ограниченная инфраструктура: один инстанс каждого сервиса в EC2 и базы данных требует мониторинга загрузки и потенциальных узких мест.

## План действий

1.  Установка Prometheus
    *   Развернуть контейнер Prometheus на отдельном EC2-инстансе или в Docker-контейнере
    *   Добавить endpoint для MES API в конфигурации Prometheus
2.  Встроить метрики в MES API
    *   добавить в проект библиотеку Prometheus для C#
    *   реализовать собственную метрики
3.  Развертывание Grafana
    *   Развернуть Grafana на отдельном EC2-инстансе или в Docker-контейнере
    *   Создать дашборд для метрик
    *   Настроить доступ к Grafana с авторизацией для администраторов и операторов
4.  Настроить алерты в Prometheus
